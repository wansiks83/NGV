# 개발 생명주기 게이트 확인 방법 (분석→설계→구현→테스트)

CLAUDE.md의 "각 단계가 완료되었을 때, 지정된 템플릿을 이용한 산출물이 생성되어야 한다"를 구현 단계 시작 시점에 적용하는 방법이다.

## 확인할 선행 산출물

| 선행 단계 | 산출물 | 만드는 스킬/서브에이전트 | 최소 확인 항목 |
|---|---|---|---|
| 분석 | 소프트웨어 요구사항 명세서(`ENG-SWE1-001`) | `requirements-analyst` | 구현 대상 기능과 관련된 요구사항 ID가 존재하고 검증기준이 정의되어 있는가 |
| 설계(아키텍처) | 소프트웨어 아키텍처 설계서(`ENG-SWE2-001`) | `architecture-designer` | 구현 대상 컴포넌트와 인터페이스가 정의되어 있는가 |
| 설계(상세) | 소프트웨어 상세설계서(`ENG-SWE3-001`) | `detailed-designer` | 구현 대상 유닛의 함수 계약·알고리즘·상태전이가 정의되어 있는가 |

## 확인 절차

1. 저장소에서 위 산출물 파일을 검색한다(파일명에 요구사항/아키텍처/상세설계, 또는 `ENG-SWE1`/`ENG-SWE2`/`ENG-SWE3` 포함 여부로 검색).
2. 찾은 문서가 구현하려는 대상 기능/유닛을 실제로 다루고 있는지 내용을 확인한다(단순히 문서가 존재한다고 통과시키지 않는다).
3. 문서가 없거나, 있어도 구현 대상 부분이 비어 있으면 구현을 시작하지 않는다. 사용자에게 어떤 산출물이 없는지, 어떤 스킬/서브에이전트로 만들 수 있는지 안내한다.
4. 사용자가 "산출물 없이 진행해달라"고 명시적으로 지시하면, 그 사실과 추적성 손실 위험을 결과물에 명시하고 진행한다. 이때도 최소한 구현 대상 함수의 입력/출력/기대 동작은 사용자에게 확인한다(근거 없이 상상해서 구현하지 않는다).

## 게이트를 생략해도 되는 경우

- 이미 완료된 구현에 대한 버그 수정처럼, 새로운 기능이 아니라 기존 동작을 유지하는 작업은 이 게이트를 매번 새로 통과할 필요는 없다. 다만 수정 대상 함수의 계약이 상세설계서와 다르게 바뀌는 경우에는 상세설계서도 함께 갱신해야 한다.
