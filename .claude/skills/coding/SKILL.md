# 구현자(coding) — Python 3.14, TDD, 품질지표 준수

## 이 스킬을 사용하는 시점

소프트웨어 상세설계(SWE.3 산출물, `detailed-designer` 스킬로 작성된 것)를 실제 Python 코드로 구현할 때, 또는 기존 코드를 CLAUDE.md의 구현 지침(품질지표, 네이밍, 주석, TDD 준수 여부)으로 점검할 때 사용한다.

## 0단계 — 개발 생명주기 게이트 확인 (CLAUDE.md 필수 정책)

CLAUDE.md는 "이 프로젝트는 반드시 분석, 설계, 구현, 테스트의 순서로 개발을 진행한다"고 규정한다. 구현을 시작하기 전에 선행 단계 산출물을 확인한다.

- **분석**: `requirements-analyst` 스킬로 작성된 소프트웨어 요구사항 명세서(`ENG-SWE1-001` 등)가 있는가.
- **설계**: `architecture-designer` 스킬로 작성된 소프트웨어 아키텍처 설계서(`ENG-SWE2-001`)와 `detailed-designer` 스킬로 작성된 소프트웨어 상세설계서(`ENG-SWE3-001`, 함수 계약·알고리즘·상태전이 포함)가 있는가.

찾지 못하면 임의로 구현을 시작하지 않는다. 먼저 해당 산출물을 만들 것을 사용자에게 안내한다(필요한 스킬/서브에이전트를 안내). 사용자가 "산출물 없이 바로 구현해달라"고 명시적으로 지시한 경우에만, 그 사실과 이로 인한 추적성 손실 위험을 산출물/커밋 메시지 등에 명시하고 진행한다. 세부 확인 방법은 `references/lifecycle-gate.md` 참고.

## 1단계 — TDD로 진행 (필수)

**항상** `Skill` 도구로 `tdd` 스킬을 로드하고, Red-Green-Refactor 절차를 따른다. 테스트보다 구현 코드를 먼저 작성하지 않는다.

## 2단계 — 설계 계약을 코드로 옮기기 (인터페이스 전용 통신 유지)

- 상세설계서의 함수 계약(입력/출력/사전조건/사후조건/부작용/예외/시간 제약)을 그대로 구현한다. 계약에 없는 동작을 임의로 추가하지 않는다.
- 유닛 간 통신은 정의된 함수/인터페이스로만 하고, 다른 모듈의 내부 상태(비공개 속성, 모듈 전역변수 등)에 직접 접근하는 코드를 작성하지 않는다.
- 응집력/결합도/SOLID 원칙(`architecture-designer` 스킬의 `references/cohesion-coupling.md`, `references/solid-principles.md`)을 클래스/함수/모듈 구조에 반영한다.
- 설계와 다르게 구현해야 할 필요가 발견되면 먼저 상세설계서를 갱신하도록 사용자에게 제안한다. 구현이 설계보다 앞서 나가지 않는다.

## 3단계 — 코딩 규칙과 품질지표 준수 (필수, 오픈소스 도구로 실측)

- 네이밍·주석 규칙은 `references/naming-and-comments.md`를 따른다(함수/변수명 3자 이상 낙타표기법, Doxygen 방식 주석 20% 이상).
- 아래 품질지표를 **반드시** 준수하고, 추측이 아니라 오픈소스 도구로 실제 측정한 값을 근거로 제시한다. 측정 방법과 도구 사용법은 `references/quality-metrics.md` 참고.
  - 함수 순수 코드 라인수 ≤ 50라인
  - 함수 순환복잡도 ≤ 10
  - 중복 코드는 7라인까지 허용(8라인 이상 중복 금지)
- 기준을 초과하면 구현을 끝내지 말고 TDD의 리팩터링 단계에서 함수 분리 등으로 해결한다. 기준을 임의로 완화하지 않는다.

## 4단계 — ISO 26262 코딩 제약과 방어적 동작 반영

- 대상 유닛에 ASIL이 있으면 `detailed-designer` 스킬의 `references/iso26262-swe3-constraints.md`에 정의된 코딩 제약(전역상태 제한, 무조건 분기 지양, 방어적 입력검증 등)을 Python 코드에 맞게 반영한다.
- 상세설계서의 "오류와 방어 동작" 절에 정의된 입력검증/오류처리/안전상태 전환을 구현한다.

## 5단계 — 관련 산출물 갱신

- 새 오픈소스 의존성을 추가했다면 `TPL-SBOM-001`(Python 의존성 SBOM/FOSS 라이선스 목록)을 갱신한다(`detailed-designer` 스킬의 `references/sbom-foss-guide.md` 참고).
- 구현한 소스 파일/함수를 상세설계 단위·요구사항과 연결하는 양방향 추적 매트릭스(`TPL-TRC-001`)를 갱신한다.
- 코드 리뷰가 필요하면 리뷰 대상 목록을 정리해 `TPL-REV-001`(단계별 인스펙션 결과) 양식에 기록할 수 있게 준비한다(실제 리뷰는 사용자/리뷰어가 수행).

## 6단계 — 완료 보고

- 품질지표 측정 결과(도구 이름, 실제 수치, 기준 대비 통과 여부)를 요약해 보고한다.
- CLAUDE.md 생명주기상 다음 단계는 "테스트"(SWE.4 소프트웨어 유닛 검증)임을 안내한다. 이 스킬은 단위검증 자체(테스트 계획서/결과서 작성)를 수행하지 않는다.
