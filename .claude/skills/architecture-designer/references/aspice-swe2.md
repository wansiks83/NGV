# A-SPICE 4.1 — SWE.2 소프트웨어 아키텍처 설계

**목적**: 소프트웨어 요구사항을 만족하는 아키텍처를 수립하고, 소프트웨어 요소를 식별하며 동적 동작을 정의한다.

**기본수행항목(BP) 요약**
- 소프트웨어 아키텍처를 개발한다(요소, 계층, 컴포넌트 구조).
- 소프트웨어 요구사항을 아키텍처 요소에 할당한다.
- 요소 간 인터페이스(내부/외부)를 정의한다.
- 아키텍처 요소들의 동적 동작(자원 사용, 타이밍, 동시성 등)을 기술한다.
- 자원 사용(메모리, CPU 등) 목표 대비 소요를 분석한다.
- 아키텍처 대안을 평가하고 근거를 남긴다.
- 아키텍처 요소에 대한 검증 기준을 정의한다.
- 소프트웨어 요구사항과 아키텍처 간 일관성·양방향 추적성을 확보한다.

**산출물 후보**
- 소프트웨어 아키텍처 설계서
- 인터페이스 명세서
- 동적 동작 기술서(시퀀스/상태 다이어그램 등)
- 소프트웨어 요구사항 ↔ 아키텍처 추적표
- 아키텍처 대안 평가 근거
- 아키텍처 검증 기준

이 요약은 공식 PAM 4.1 원문의 재구성이며, 정확한 조문이 필요하면 공식 문서를 확인해야 한다. BP 순서는 이 스킬의 1~6단계와 다음처럼 대응한다.

| 이 스킬의 단계 | 대응하는 BP |
|---|---|
| 2단계(후보 구조 제안) | 아키텍처 대안 평가 |
| 3단계(원칙 적용) | 아키텍처 개발, 요구사항 할당 |
| 4단계(인터페이스 정의) | 인터페이스 정의 |
| 4~5단계 | 동적 동작 기술 |
| 6단계(검증/추적) | 검증 기준 정의, 추적성·일관성 확보 |
