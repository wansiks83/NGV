# 컴포넌트 통합 순서 정의 가이드

아키텍처 설계 단계에서 정의하는 통합 순서는 이후 A-SPICE SWE.5(소프트웨어 통합 및 통합 검증)의 통합 전략 입력이 된다. 순서는 반드시 컴포넌트 간 의존관계에 근거해야 하며, 임의로 정하지 않는다.

## 절차

1. **의존관계 파악**: 각 컴포넌트가 어떤 컴포넌트의 인터페이스를 요구하는지(요구 인터페이스 → 제공 인터페이스) 표로 정리한다.
2. **의존관계 그래프 작성**: 컴포넌트를 노드로, 의존을 화살표로 표현한다(요구하는 쪽 → 제공하는 쪽). 순환 의존이 있으면 먼저 아키텍처를 재검토해 제거한다(순환 의존이 있으면 통합 순서 자체를 정할 수 없다).
3. **통합 전략 선택**: 아래 전략 중 이 아키텍처와 프로젝트 상황에 맞는 것을 선택한다.
   - **상향식**: 의존을 받는 하위 컴포넌트부터 통합. 하위 컴포넌트의 안정성을 먼저 확보할 수 있으나, 상위 수준의 전체 동작 확인이 늦어진다.
   - **하향식**: 상위(제어) 컴포넌트부터 통합하고 하위는 임시 대체물로 대체. 전체 흐름을 일찍 확인할 수 있으나 대체물 개발 부담이 있다.
   - **점진적(위험 기반)**: 리스크가 높거나 핵심적인 컴포넌트(예: 안전 관련, 성능 병목 우려)를 먼저 통합해 문제를 조기에 발견한다.
4. **통합 단계 정의**: 선택한 전략에 따라 몇 개의 단계로 나누고, 각 단계마다 다음을 명시한다.
   - 이번 단계에서 통합되는 컴포넌트 목록
   - 전제조건(이전 단계에서 통합이 완료·검증된 컴포넌트, 필요한 대체물/모의 구현체)
   - 이번 단계에서 확인할 수 있는 동작(통합 후 어떤 시나리오가 검증 가능해지는가)

## 순서 결정 시 우선 고려 사항

- ASIL이 높은 컴포넌트 또는 안전 메커니즘과 관련된 컴포넌트는 가능한 한 이른 단계에서 통합해, 통합 문제를 조기에 발견한다.
- 다른 여러 컴포넌트가 의존하는(팬인이 높은) 컴포넌트는 먼저 통합해야 이후 단계 병렬 진행이 가능해진다.
- 외부 하드웨어/장비가 필요한 컴포넌트는 그 가용 시점을 통합 일정에 반영한다.

## 산출물 형식 (예시)

| 단계 | 통합 대상 컴포넌트 | 전제조건 | 확인 가능한 동작 |
|---|---|---|---|
| 1 | 센서모듈 | 없음(최하위) | 센서 원시값 취득 |
| 2 | 판단모듈 | 1단계 완료, 센서모듈 인터페이스 확정 | 장애물 거리 기반 판단 로직 |
| 3 | 제동모듈 | 2단계 완료 | 판단 결과에 따른 제동 명령 출력 |
| 4 | 전체 통합 | 1~3단계 완료 | 센서 입력부터 제동까지 전체 시나리오 |
