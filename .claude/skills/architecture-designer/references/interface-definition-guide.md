# 컴포넌트 인터페이스 정의 가이드

컴포넌트는 반드시 인터페이스를 통해서만 통신한다. 내부 데이터·내부 상태에 대한 직접 접근(같은 프로세스 내 전역변수 공유, 다른 컴포넌트 구조체 필드 직접 참조 등)은 허용하지 않는다.

## 인터페이스 명세에 반드시 포함할 항목

1. **식별자와 방향**: 인터페이스 이름, 제공 인터페이스인지 요구 인터페이스인지.
2. **연산/데이터 목록**: 인터페이스가 노출하는 함수·서비스·이벤트·데이터 항목.
3. **입출력 파라미터**: 각 파라미터의 이름, 자료형, 단위(물리량인 경우), 유효 범위.
4. **사전조건**: 호출 전에 만족해야 하는 조건(예: 초기화 완료 여부, 파라미터 범위).
5. **사후조건**: 호출 후 보장되는 결과(정상 처리 시 상태·반환값).
6. **오류/예외 처리**: 사전조건 위반, 내부 오류 발생 시 어떻게 알리는지(오류 코드, 예외, 콜백 등)와 호출자가 취해야 할 조치.
7. **시간 제약**: 응답시간, 호출 주기, 타임아웃 등 실시간 요구가 있는 경우 명시.
8. **ASIL/무결성 요구**: 인터페이스를 통해 전달되는 데이터에 무결성 확인(체크섬, 시퀀스 카운터 등)이 필요한 경우 명시.

## 작성 원칙

- 인터페이스는 사용하는 컴포넌트 관점에서 "무엇을 할 수 있는가"를 기술한다. 제공 컴포넌트의 내부 구현 방식을 노출하지 않는다.
- 하나의 인터페이스에 서로 무관한 기능을 몰아넣지 않는다(인터페이스 분리 원칙 — `references/solid-principles.md` 참고).
- 인터페이스 변경은 이를 사용하는 모든 컴포넌트에 영향을 미치므로, 변경 시 영향받는 컴포넌트 목록을 함께 기록한다.
- 인터페이스 이름·파라미터명은 요구사항 문서와 아키텍처 문서 전체에서 동일한 용어를 사용한다.

## 예시

| 항목 | 내용 |
|---|---|
| 인터페이스 | `IObstacleSensor`(제공: 센서모듈, 요구: 판단모듈) |
| 연산 | `getObstacleDistance(): 거리(m), 신뢰도(0~1)` |
| 사전조건 | 센서모듈이 초기화 완료 상태(`INITIALIZED`)여야 한다 |
| 사후조건 | 유효한 측정값이 있으면 거리·신뢰도를 반환하고, 없으면 오류코드 `NO_DATA`를 반환한다 |
| 시간 제약 | 호출 후 10ms 이내 응답 |
| 오류 처리 | `NO_DATA` 반환 시 판단모듈은 이전 유효값을 최대 3주기까지 유지 후 안전상태로 전환 |
