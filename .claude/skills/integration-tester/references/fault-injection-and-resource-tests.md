# 결함주입시험·자원사용시험 설계 가이드

## 결함주입시험

**목적**: 한 컴포넌트가 오류를 발생시켰을 때, 이를 사용하는 다른 컴포넌트가 상세설계서의 "오류와 방어 동작"에 정의된 대로 반응하는지 확인한다.

**설계 절차**
1. 상세설계서/함수 계약에서 각 인터페이스의 오류·예외 처리 정의를 모두 나열한다(예: 사전조건 위반 시 오류코드 반환, 타임아웃 시 이전값 유지 등).
2. 각 오류 상황을 실제로 발생시키는 방법을 정한다(제공 컴포넌트가 정의된 오류코드/예외를 반환하도록 시험용 입력 또는 대체 구현으로 유도).
3. 오류가 발생했을 때 호출 컴포넌트가 정의된 대응(안전상태 전환, 재시도, 이전값 유지 등)을 실제로 수행하는지 확인하는 단언(assert)을 작성한다.
4. `TPL-SWE5-002`의 `Technique` 열에 "결함주입시험"을 기록하고, `Trace`에 대상 오류 처리 정의(상세설계서 절/함수 계약)를 연결한다.

**주의**: 결함주입은 제공 컴포넌트의 내부 구현을 조작하는 것이 아니라, 그 컴포넌트가 계약상 낼 수 있는 오류 결과(정의된 오류코드/예외)를 실제로 내도록 입력을 조작하는 것이다. 계약에 없는 임의의 오류를 인위적으로 주입하지 않는다.

## 자원사용시험

**목적**: 통합된 상태에서 자원 사용(실행시간, 메모리, 호출 빈도 등)이 아키텍처 설계서에 명시된 한도 내에 있는지 확인한다.

**설계 절차**
1. 아키텍처 설계서에서 자원 관련 제약(응답시간 한도, 메모리 상한, 호출 주기 등)을 모두 나열한다.
2. 각 제약마다, 실제 통합된 환경에서 해당 값을 측정하는 방법을 정한다(예: 함수 호출 전후 시각 측정, `tracemalloc`으로 메모리 사용량 측정).
3. 측정값이 한도를 넘는지 판정하는 단언을 작성한다.
4. 측정은 대표적인 부하 상황(최대 통합 컴포넌트 수, 최대 입력 빈도 등)에서 수행한다. 단일 최소 조건에서만 측정해 통과시키지 않는다.

**Python에서 측정에 쓸 수 있는 오픈소스/표준 도구**
- 실행시간: 표준 라이브러리 `time.perf_counter()`로 직접 측정하거나, `pytest-benchmark`(오픈소스) 사용.
- 메모리: 표준 라이브러리 `tracemalloc`.

측정 결과는 `TPL-SWE5-003`의 `Actual Result`에 실제 수치를 기록하고, 한도 초과 시 `Result`를 실패로, `Defect ID`를 연결한다.
