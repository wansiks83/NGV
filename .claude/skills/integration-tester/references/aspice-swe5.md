# A-SPICE 4.1 — SWE.5 소프트웨어 통합 및 통합검증

**목적**: 소프트웨어 요소/유닛을 통합하고, 통합된 소프트웨어가 아키텍처 설계를 만족함을 검증한다.

**기본수행항목(BP) 요약**
- 소프트웨어 통합 전략(순서, 단계)을 개발한다.
- 통합 검증 기준 및 회귀 시험 전략을 개발한다.
- 통합 테스트 사양(테스트 케이스)을 개발한다.
- 소프트웨어 요소를 계획에 따라 통합한다.
- 통합 테스트를 수행하고 결과를 기록한다.
- 아키텍처 ↔ 통합 테스트 간 일관성·추적성을 확보한다.

**산출물 후보**
- 소프트웨어 통합 전략/계획
- 통합 테스트 사양
- 통합 테스트 결과
- 회귀 시험 전략
- 아키텍처 ↔ 통합 테스트 추적표

이 요약은 공식 PAM 4.1 원문의 재구성이며, 정확한 조문이 필요하면 공식 문서를 확인해야 한다.

## 이 스킬의 단계 ↔ BP ↔ 템플릿 절 대응

| 이 스킬의 단계 | 대응 BP | TPL-SWE5-001 절 |
|---|---|---|
| 1단계(테스트 베이시스 확인) | 통합 전략 개발(입력) | 2~3절 |
| 3단계(통합 순서에 따른 단계 설계) | 통합 전략 개발 | 3~5절 |
| 4단계(인터페이스 기반 케이스 설계) | 통합 테스트 사양 개발 | 6~7절, `TPL-SWE5-002` |
| 5단계(커버리지) | 통합 검증 기준 개발 | 5절(종료기준)에 반영 |
| 6단계(실행/회귀) | 통합 수행, 결과 기록 | 8~10절, `TPL-SWE5-003` |
| 7단계(추적성) | 일관성·추적성 확보 | 11~14절 |

## SWE.2 → SWE.3/coding → SWE.5 흐름에서 이 스킬의 위치

- **입력**: `architecture-designer`의 아키텍처 설계서(인터페이스, 통합 순서), `detailed-designer`의 상세설계서, `coding`이 구현한 소스 코드.
- **이 스킬의 출력**: 통합전략/시험명세서, 통합시험 케이스, 통합시험 결과서.
- **다음 단계로의 연결**: 이 스킬의 산출물은 이후 SWE.6(소프트웨어 자격시험)의 입력이 되며, 결함은 결함관리(`TPL-SUP9-001`)와 연결된다.
