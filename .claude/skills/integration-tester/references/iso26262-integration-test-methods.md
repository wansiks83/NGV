# ISO 26262 Part 6 — 소프트웨어 통합시험 기법

ISO 26262 Part 6는 소프트웨어 통합시험에 적용할 시험기법, 시험케이스 도출기법, 구조적 커버리지 지표를 규정한다. 아래는 그 취지를 요약한 것이며, 정확한 조문과 ASIL별 권고/필수 구분표는 공식 표준을 확인해야 한다.

## 시험기법 (무엇을 확인하는가)

- **요구사항기반시험**: 소프트웨어 요구사항(및 인터페이스가 지원해야 하는 시스템 동작)이 통합된 상태에서 만족되는지 확인한다. 가장 기본이 되는 기법이며 모든 통합 단계에 적용한다.
- **인터페이스시험**: 컴포넌트 간 인터페이스(아키텍처 설계서의 제공/요구 인터페이스)가 계약대로 동작하는지 확인한다. 파라미터 타입/범위, 호출 순서, 사전·사후조건, 오류 코드 전달이 대상이다.
- **결함주입시험**: 한 컴포넌트가 비정상 입력·오류를 발생시켰을 때, 이를 사용하는 다른 컴포넌트가 정의된 오류 처리·안전상태 전환을 실제로 수행하는지 확인한다. 상세설계서의 "오류와 방어 동작"에 정의된 내용이 대상이다.
- **자원사용시험**: 통합된 상태에서 CPU, 메모리, 통신 대역 등 자원 사용이 설계된 한도 내에 있는지 확인한다.
- **모델-코드 백투백비교시험**: 모델 기반 설계를 사용하는 경우, 모델의 동작과 통합된 코드의 동작이 동일한 입력에 대해 같은 결과를 내는지 비교한다(모델 기반 설계를 사용하지 않는 프로젝트에는 적용하지 않는다).

이 프로젝트는 통합 단계마다 최소한 요구사항기반시험과 인터페이스시험을 적용하고, 오류 처리/자원 제약이 설계에 명시된 컴포넌트에는 결함주입시험과 자원사용시험을 추가로 적용한다.

## 시험케이스 도출기법 (케이스를 어떻게 뽑는가)

시험기법(위)이 "무엇을 확인할지"를 정하면, 실제 입력값·조건 조합을 어떻게 뽑을지는 공용 스킬 `test-design-techniques`의 카탈로그(경계값분석/동치분할/조합·페어와이즈/엣지케이스/경험기반/의사결정표기반/상태전이기반/사전조건·사후조건검증/회귀테스트)를 그대로 따른다. 이 파일에서 별도로 다시 정의하지 않는다. 인터페이스 계약(사전조건/사후조건)이나 상세설계서의 의사결정표·상태전이표가 있으면 그로부터 기법을 도출한다.

## 구조적 커버리지 지표 — 함수커버리지·콜커버리지

ISO 26262 Part 6는 소프트웨어 통합시험 단계의 구조적 커버리지 지표로 **함수커버리지**와 **콜커버리지**를 규정한다.

- **함수커버리지**: 통합된 소프트웨어의 모든 함수(아키텍처 인터페이스가 노출하는 연산 포함)가 시험 중 최소 1회 호출되었는가의 비율.
- **콜커버리지**: 코드에 존재하는 모든 함수 호출 지점(호출문)이 시험 중 최소 1회 실행되었는가의 비율. 함수커버리지보다 더 세밀한 지표로, 같은 함수를 호출하는 여러 호출 지점을 모두 구분해서 본다.

이 프로젝트는 두 지표 모두 **100%**를 목표로 한다(ASIL과 무관하게 프로젝트 정책으로 강제). 측정 방법은 `references/coverage-measurement.md`를 따른다. 100%에 도달하지 못하는 부분이 남으면, 임의로 기준을 낮추지 않고 그 이유(도달 불가능한 방어적 코드 등)를 근거와 함께 사용자에게 보고하고 승인을 받는다.
