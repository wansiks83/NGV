# 요구사항 명확성·일관성 체크리스트

요구사항 작성을 마치면 아래 항목으로 자체 점검한다. 하나라도 걸리면 해당 요구사항을 수정한 뒤 다음 단계로 넘어간다.

## 명확성 체크리스트

- [ ] 한 요구사항에 "그리고", "또한", "및" 등으로 여러 요구가 묶여 있지 않은가(원자성).
- [ ] 대명사("그것", "이것", "해당 시스템" 등)가 무엇을 가리키는지 모호하지 않은가.
- [ ] "적절히", "충분히", "가능한 한", "일반적으로" 같은 정성적 표현이 수치·조건 없이 쓰이지 않았는가.
- [ ] 업계 약어·은어를 처음 사용할 때 풀어서 설명했는가.
- [ ] 능동태로, 주어(누가/무엇이)와 행위(무엇을 해야 하는가)가 분명한 문장인가.
- [ ] 배경지식이 없는 제3자가 읽어도 하나의 의미로만 해석되는가.

## 일관성 체크리스트

- [ ] 같은 대상·개념을 요구사항마다 다른 용어로 부르고 있지 않은가(용어집을 만들어 통일했는가).
- [ ] 이 요구사항이 상위 요구사항(시스템 요구사항, 안전목표 등)과 모순되지 않는가.
- [ ] 이 요구사항이 동일 문서 내 다른 요구사항과 서로 모순되는 조건을 요구하지 않는가.
- [ ] 동일한 수치·조건을 여러 요구사항에서 참조할 때 값이 일치하는가(예: 같은 응답시간 기준이 문서 곳곳에서 다르게 적혀 있지 않은가).
- [ ] 요구사항 ID 체계(접두어, 번호 규칙)가 문서 전체에서 통일되어 있는가.
- [ ] 다이어그램에 등장하는 요소명이 텍스트 요구사항의 용어와 일치하는가.

## 점검 결과 기록

점검 결과 수정한 항목이 있다면, 무엇을 어떻게 고쳤는지 간단히 기록해 두면 이후 리뷰(A-SPICE PA2.2 산출물 관리 관점의 검토 기록)에 활용할 수 있다.
