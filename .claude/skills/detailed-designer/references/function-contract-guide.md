# 핵심 함수 계약 작성 가이드

아키텍처 수준의 인터페이스 계약(`architecture-designer` 스킬의 `references/interface-definition-guide.md`)을 함수/메서드 단위까지 구체화한 것이다. 유닛 간 통신은 반드시 이 계약을 통해서만 이루어져야 한다.

## 함수 계약에 반드시 포함할 항목

1. **식별자**: 함수/메서드 이름, 소속 유닛.
2. **입력 파라미터**: 이름, 자료형, 단위(물리량인 경우), 유효 범위.
3. **출력/반환값**: 자료형, 의미, 유효 범위.
4. **사전조건**: 호출 전 호출자가 보장해야 하는 조건(초기화 여부, 파라미터 범위 등). 사전조건 위반 시 함수가 어떻게 반응하는지도 명시한다.
5. **사후조건**: 정상 종료 시 보장되는 상태·반환값.
6. **부작용**: 파라미터 외에 함수가 변경하는 상태(내부 상태, 로그 기록 등). 부작용이 없으면 "없음"이라고 명시한다.
7. **예외/오류 처리**: 오류 발생 시 반환값/예외/콜백 중 무엇으로 알리는지와 호출자가 취할 조치.
8. **시간 제약**: 최대 실행시간, 호출 주기 제한 등(실시간 요구가 있는 경우).

## 작성 원칙

- 계약은 호출자 관점에서 "무엇을 호출하면 무엇이 보장되는가"를 기술한다. 내부 구현 알고리즘은 6단계(핵심 알고리즘)에서 별도로 다룬다.
- 사전조건을 구현체가 더 강하게 요구하거나 사후조건을 더 약하게 보장하면 안 된다(리스코프 치환 원칙 — `architecture-designer` 스킬의 `references/solid-principles.md` 참고). 같은 인터페이스를 구현하는 여러 유닛이 있다면 계약을 동일하게 지켜야 한다.
- 함수 계약에 없는 방식으로 다른 유닛의 상태를 읽거나 쓰지 않는다(전역변수 공유, 내부 필드 직접 접근 금지).

## 예시

| 항목 | 내용 |
|---|---|
| 함수 | `calculateTimeToCollision(distance_m, relativeSpeed_mps): ttc_s` |
| 소속 유닛 | 판단모듈 |
| 입력 | `distance_m`(0 이상 실수), `relativeSpeed_mps`(실수) |
| 출력 | `ttc_s`: 충돌예상시간(초). 상대속도가 0 이하(접근하지 않음)면 `INFINITY` 반환 |
| 사전조건 | `distance_m >= 0` |
| 사후조건 | 반환값은 음수가 될 수 없다 |
| 부작용 | 없음 |
| 오류 처리 | `distance_m < 0`이면 오류코드 `INVALID_INPUT` 반환, 계산 수행하지 않음 |
| 시간 제약 | 호출 후 1ms 이내 반환 |
