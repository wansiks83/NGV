# 유닛 수준 설계 기법: 의사코드/흐름도, 정책 의사결정표, 상태전이 상세

## 핵심 알고리즘 (양식 6절)

- 처리 순서, 판단 조건, 경계값, 계산 근거를 의사코드 또는 흐름도로 작성한다.
- 의사코드는 실제 구현 언어 문법에 얽매이지 않되, 조건문/반복문/함수 호출 구조가 실제 구현과 1:1로 대응되도록 작성한다.
- 경계값(최소/최대/0/음수 등)에서의 동작을 반드시 명시한다.

## 정책 의사결정표 (양식 7절)

여러 입력 조건의 조합에 따라 동작이 달라지는 로직은 표로 작성해 누락·모순을 방지한다.

| 조건1 | 조건2 | 조건3 | 기대 동작 | 우선순위/충돌 해결 |
|---|---|---|---|---|
| 참 | 참 | - | 동작 A | 조건1·2 동시 충족 시 A 우선 |
| 참 | 거짓 | 참 | 동작 B | |
| 거짓 | - | - | 동작 C(기본값) | 다른 조건과 무관하게 적용 |

작성 시 점검할 것:
- 모든 조건 조합이 표에 정의되어 있는가(빠짐없이 다루었는가).
- 두 행이 동시에 만족될 수 있는 경우 우선순위/충돌 해결 규칙이 명시되어 있는가.
- "그 외"/기본값 행이 있는가.

## 상태전이 상세 (양식 8절)

아키텍처 수준의 상태기계(`requirements-analyst` 스킬 `references/uml-sysml-guide.md`의 상태기계 다이어그램)를 유닛 구현 수준까지 구체화한다.

- **상태 저장 위치**: 상태값을 어떤 변수/자료구조에 저장하는지.
- **전이 함수**: 상태 전이를 실제로 수행하는 함수/코드 위치.
- **이벤트**: 전이를 유발하는 이벤트(함수 호출, 신호 수신, 타이머 만료 등).
- **가드 조건**: 이벤트가 발생해도 조건을 만족해야만 전이가 일어나는 경우의 조건.
- **타이머**: 시간 기반 전이가 있는 경우 타이머 시작/종료/재설정 규칙.
- **초기화 동작**: 시스템/유닛 시작 시 초기 상태와 초기화 절차.

| 현재 상태 | 이벤트 | 가드 | 다음 상태 | 진입 동작 |
|---|---|---|---|---|
| 대기 | 장애물 인식 | 신뢰도 ≥ 0.8 | 감지중 | 타이머 시작 |
| 감지중 | 충돌예상시간 계산 완료 | ttc < 임계값 | 제동중 | 제동 명령 발행 |

## 다이어그램과의 연결

위 세 기법(의사코드/흐름도, 의사결정표, 상태전이표)은 문서(TPL-SWE3-001)의 텍스트/표로 작성하고, 호출 순서나 구조 자체는 `TPL-SWE3-002` 드로우아이오 양식에 시각화해 상호 참조시킨다.
