# ISO 26262 Part 6 — 코딩 수준 설계 제약 (SWE.3 적용)

아키텍처 수준(SWE.2)에서 다루지 않고 상세설계/구현 수준(SWE.3)에서 구체화해야 하는 ISO 26262 Part 6의 설계·코딩 원칙을 정리한다. 정확한 조문과 ASIL별 권고/필수 구분표는 공식 표준을 확인해야 한다.

## 자료형과 변수

- **강한 타입 지정**: 암묵적 형변환에 의존하지 않고, 자료형과 단위를 명시적으로 정의한다(4단계 "공통 자료형"에 반영).
- **전역변수 제한**: 유닛 간 데이터 공유를 전역변수로 하지 않는다. 반드시 함수 계약(5단계)을 통해 전달한다. 불가피하게 전역 상태가 필요하면 그 소유 유닛과 접근 방법을 명시한다.

## 자원 사용

- **포인터 사용 제한**: ASIL이 높은 유닛일수록 포인터 연산(포인터 산술, 함수 포인터의 동적 변경 등)을 제한한다. 사용이 필요하면 유효성 검사 방법을 함께 기술한다.
- **동적 메모리 할당 제한**: 런타임 동적 할당(런타임 중 메모리 할당/해제)은 ASIL이 높은 유닛에서는 원칙적으로 지양하고, 초기화 시점의 정적/고정 할당으로 대체하는 것을 우선 검토한다. 불가피한 경우 실패 처리 방법(할당 실패 시 동작)을 명시한다.
- **인터럽트 사용 제한**: 인터럽트를 사용하는 유닛은 우선순위, 최대 처리시간, 재진입성(다시 호출되어도 안전한지)을 명시한다.

## 제어 흐름

- **무조건 분기 지양**: `goto`류의 무조건 분기를 피하고, 구조적 제어문(조건문/반복문/함수 호출)으로 흐름을 예측 가능하게 유지한다.
- **단일 진입·단일 종료**: 함수는 하나의 진입점과 명확한 종료 조건을 갖도록 설계한다(6단계 알고리즘 설계에 반영).

## 방어적 설계 (7단계 "오류와 방어 동작"에 반영)

- 입력 유효성 검사: 함수 계약의 사전조건을 코드 수준에서 실제로 검사하는 방법(방어적 프로그래밍)을 명시한다.
- 실패 시 안전상태 전환: 사전조건 위반, 자원 실패, 예외 발생 시 어떤 안전상태로 전환하는지, 그 상태에서 무엇을 보장하는지 기술한다.
- 진단 정보: 오류 발생 시 남겨야 하는 로그/진단 데이터를 정의한다.

## ASIL별 적용 수준

- 이 목록의 각 제약은 ASIL이 높아질수록 더 엄격하게(원칙적으로 금지에 가깝게) 적용한다. ASIL이 없는(QM) 유닛에는 모든 항목을 강제하지 않아도 되지만, 상세설계서에는 "이 유닛에는 어떤 제약을 적용했고 어떤 것을 적용하지 않았는지, 그 이유"를 명시한다.
- 근거 없이 제약을 생략하지 않는다. 생략 시 이유(예: QM 유닛, 성능 요구상 불가피 등)를 반드시 기록한다.
