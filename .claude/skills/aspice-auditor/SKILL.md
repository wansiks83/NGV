# A-SPICE 4.1 감사원 (SWE 프로세스 / CL1~CL2)

## 이 스킬을 사용하는 시점

저장소 안의 소프트웨어 엔지니어링 산출물(요구사항, 아키텍처/상세설계, 소스코드, 각종 시험 결과, 추적성 매트릭스 등)을 오토모티브 스파이스 4.1 기준 CL1~CL2 관점에서 점검하라는 요청을 받았을 때 사용한다.

## 감사 방법론

1. **대상 산출물 수집** — 저장소에서 아래 산출물 후보를 찾는다(파일명·폴더명·문서 제목 기준으로 유사한 것도 포함):
   - 소프트웨어 요구사항 명세, 시스템 요구사항 ↔ SW 요구사항 추적표
   - 소프트웨어 아키텍처 설계, 인터페이스 정의, 동적 동작 기술서
   - 소프트웨어 상세설계, 소스코드, 코딩 가이드라인/정적분석 규칙
   - 단위 검증 절차·결과, 코드 리뷰/정적분석 결과, 커버리지 리포트
   - 통합 전략·통합 테스트 사양·통합 테스트 결과
   - SW 자격시험 전략·사양·결과
   - 프로젝트 계획, 일정/자원 계획, 회의록·리뷰 기록, 형상관리(버전관리) 이력, 변경관리 기록
2. **프로세스 매핑** — 찾은 산출물을 `references/swe-processes.md`의 SWE.1~SWE.6에 매핑한다.
3. **CL1 판정** — 각 프로세스의 기본수행항목(BP)이 실제로 수행되었다는 증거(산출물 존재 + 내용의 충실성)가 있는지 확인한다.
4. **CL2 판정** — CL1을 넘어 "관리되고 있다"는 증거를 확인한다. 즉 계획 대비 수행, 책임/권한 정의, 검토(리뷰) 기록, 형상관리, 산출물 요구사항 정의 여부 등이다. 자세한 체크리스트는 `references/cl2-generic-practices.md` 참고.
5. **등급 부여** — `references/rating-scale.md`의 NPLF 척도로 BP/GP 단위 등급을 매기고, PA(프로세스 속성) 단위로 종합한다.
6. **결과 보고** — 아래 "출력 형식"에 따라 Markdown 표로 정리한다.

## 점검 대상 프로세스

SWE.1(SW 요구사항 분석) ~ SWE.6(SW 자격시험)의 목적, 기본수행항목(BP) 요약, 산출물 목록은 `references/swe-processes.md`를 참고한다.

## 증거가 없을 때의 처리

산출물이 저장소에 전혀 없다고 해서 곧바로 N(미달성)으로 단정하지 않는다. "증거 없음(저장소에서 확인되지 않음)"으로 기록하고, 실제 산출물이 다른 도구(ALM, 형상관리 시스템, 문서저장소 등)에 있는지 사용자에게 확인을 요청한다. 코드가 전혀 없는 저장소라면 그 사실을 먼저 보고한다.

## 출력 형식

감사 결과는 항상 다음 구조의 Markdown 표로 보고한다.

| 프로세스 | BP/GP | 증거(파일 경로 등) | 등급(N/P/L/F) | 미흡사항 | 권고사항 |
|---|---|---|---|---|---|

표 아래에 프로세스별 PA1.1 / PA2.1 / PA2.2 종합 등급과, CL2 달성 여부에 대한 결론을 한 문단으로 덧붙인다(판정 규칙은 `references/rating-scale.md` 참고).

## 주의사항

이 스킬은 VDA QMC / intacs가 발행한 공식 오토모티브 스파이스 PAM 4.1 문서의 구조를 요약·재구성한 감사 보조 자료이며, 표준 원문을 그대로 인용한 것이 아니다. 실제 인증심사나 계약상 공식 등급이 필요한 경우, 반드시 공식 PAM 4.1 원문 및 인증심사원의 판단과 대조해야 하며, 이 체크리스트만으로 공식 등급을 확정해서는 안 된다.
