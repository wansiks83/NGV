# SWE.1~SWE.6 프로세스 요약 (오토모티브 스파이스 4.1)

각 프로세스마다 목적, 기본수행항목(BP) 요약, 산출물 후보를 정리한다. BP 번호와 문구는 공식 PAM 4.1 원문의 요약·재구성이며, 정확한 법적 문구가 필요하면 공식 문서를 확인해야 한다.

## SWE.1 — 소프트웨어 요구사항 분석

**목적**: 시스템 요구사항 중 소프트웨어에 할당된 부분과 인터페이스를 분석하여, 일관되고 검증 가능한 소프트웨어 요구사항을 도출한다.

**BP 요약**
- 소프트웨어 요구사항을 명세한다.
- 요구사항을 구조화한다(예: 기능 그룹, 우선순위).
- 요구사항의 정확성·기술적 타당성을 분석한다.
- 요구사항 변경이 미치는 영향(안전성, 인터페이스, 기존 설계 등)을 분석한다.
- 각 요구사항에 대한 검증 기준을 정의한다.
- 시스템 요구사항과 소프트웨어 요구사항 간 양방향 추적성과 일관성을 확보한다.
- 이해관계자와 요구사항에 대한 합의를 도출하고 의사소통한다.

**산출물 후보**
- 소프트웨어 요구사항 명세서(SRS)
- 시스템 요구사항 ↔ SW 요구사항 추적표
- 요구사항별 검증 기준 목록
- 요구사항 변경영향분석 기록

## SWE.2 — 소프트웨어 아키텍처 설계

**목적**: 소프트웨어 요구사항을 만족하는 아키텍처를 수립하고, 소프트웨어 요소를 식별하며 동적 동작을 정의한다.

**BP 요약**
- 소프트웨어 아키텍처를 개발한다(요소, 계층, 컴포넌트 구조).
- 소프트웨어 요구사항을 아키텍처 요소에 할당한다.
- 요소 간 인터페이스(내부/외부)를 정의한다.
- 아키텍처 요소들의 동적 동작(리소스 사용, 타이밍, 동시성 등)을 기술한다.
- 자원 사용(메모리, CPU 등) 목표 대비 소요를 분석한다.
- 아키텍처 대안을 평가하고 근거를 남긴다.
- 아키텍처 요소에 대한 검증 기준을 정의한다.
- SW 요구사항과 아키텍처 간 일관성·추적성을 확보한다.

**산출물 후보**
- 소프트웨어 아키텍처 설계서
- 인터페이스 명세서
- 동적 동작(시퀀스/상태 다이어그램 등) 기술서
- SW 요구사항 ↔ 아키텍처 추적표
- 아키텍처 검증 기준

## SWE.3 — 소프트웨어 상세설계 및 유닛 구현

**목적**: 소프트웨어 요소를 이해·구현 가능한 유닛 단위로 상세 설계하고 소스 코드를 구현한다.

**BP 요약**
- 아키텍처 요소별 상세설계(알고리즘, 자료구조 등)를 개발한다.
- 유닛 간 인터페이스를 정의한다.
- 유닛의 동적 동작을 기술한다.
- 상세설계를 평가한다(리뷰 등).
- 유닛에 대한 검증 기준을 정의한다.
- 상세설계에 따라 소스 코드(유닛)를 구현/개발한다.
- 아키텍처 ↔ 상세설계 ↔ 코드 간 일관성·추적성을 확보한다.

**산출물 후보**
- 소프트웨어 상세설계서
- 소스 코드
- 코딩 가이드라인 및 준수 확인 기록(정적분석 룰셋 등)
- 아키텍처 ↔ 상세설계 추적표
- 유닛 검증 기준

## SWE.4 — 소프트웨어 유닛 검증

**목적**: 소프트웨어 유닛이 상세설계 및 비기능 요구사항(코딩 표준 등)을 만족함을 검증한다.

**BP 요약**
- 유닛 검증 절차/기준을 개발한다.
- 유닛 검증의 커버리지 기준(구조 커버리지 등)을 결정한다.
- 정적 검증(코드 리뷰, 정적분석)을 수행한다.
- 유닛 테스트를 수행한다.
- 검증 결과를 분석하고 불일치를 처리한다.
- 상세설계 ↔ 유닛 검증(테스트 케이스) 간 일관성·추적성을 확보한다.

**산출물 후보**
- 유닛 검증(테스트) 절차/사양
- 유닛 테스트 결과
- 코드 리뷰/정적분석 결과
- 커버리지 리포트
- 상세설계 ↔ 유닛 테스트 추적표

## SWE.5 — 소프트웨어 통합 및 통합 검증

**목적**: 소프트웨어 요소/유닛을 통합하고, 통합된 소프트웨어가 아키텍처 설계를 만족함을 검증한다.

**BP 요약**
- 소프트웨어 통합 전략(순서, 단계)을 개발한다.
- 통합 검증 기준 및 회귀 시험 전략을 개발한다.
- 통합 테스트 사양(테스트 케이스)을 개발한다.
- 소프트웨어 요소를 계획에 따라 통합한다.
- 통합 테스트를 수행하고 결과를 기록한다.
- 아키텍처 ↔ 통합 테스트 간 일관성·추적성을 확보한다.

**산출물 후보**
- 소프트웨어 통합 전략/계획
- 통합 테스트 사양
- 통합 테스트 결과
- 회귀 시험 전략
- 아키텍처 ↔ 통합 테스트 추적표

## SWE.6 — 소프트웨어 자격시험

**목적**: 통합된 소프트웨어가 정의된 소프트웨어 요구사항을 만족함을 검증한다.

**BP 요약**
- 소프트웨어 자격시험 전략 및 회귀 시험 전략을 개발한다.
- 자격시험 사양(테스트 케이스)을 개발한다.
- 시험 환경의 대표성/적합성을 확인한다.
- 자격시험을 수행하고 결과를 기록한다.
- 소프트웨어 요구사항 ↔ 자격시험 간 일관성·추적성을 확보한다.

**산출물 후보**
- 소프트웨어 자격시험 전략/계획
- 자격시험 사양
- 자격시험 결과
- 소프트웨어 요구사항 ↔ 자격시험 추적표
