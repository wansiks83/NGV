## 1. 목적 및 적용범위

`ENG-SWE1-001`의 각 SWR이 실제로 어떤 상호작용 흐름에서 발생하는지 Use Case로 구체화한다.

## 2. 액터와 시스템 경계

| 액터 | 역할 |
|---|---|
| 운전자 | 물리버튼/AVN/음성/모바일앱으로 명령 입력 |
| 차량(Vehicle) | 차속, 기어, 충돌상태, 접근위험, 화재/과온/성인탑승, ISOFIX, ignition, sensor_fault 신호 제공 |
| Display(Web 시뮬레이터) | 상태조회 요청 및 결과 표시 |
| Actuator model | SW가 결정한 LOCK/RELEASE 출력을 받는 대상(PC/SIL 논리까지만) |

시스템 경계: 후석 좌/우 전자식 차일드락 제어 SW(Python 3.14, PC/SIL). 도어 래치 물리 구동, 센서 원시 신호 처리는 경계 밖이다.

## 4. Use Case 상세

### UC-01 운전자 명령 처리

- **기본정보**: 운전자가 물리버튼/AVN/음성/모바일앱 중 하나로 LOCK/RELEASE와 대상(LEFT/RIGHT/ALL)을 입력한다.
- **사전조건**: 입력이 유효(등록된 enum, 필수값 존재)하다.
- **기본흐름**: 1) 운전자가 명령 입력 2) SW가 `side`/`action`/`source`를 파싱 3) 다른 우선순위 로직(UC-03~09)에 의한 억제가 없으면 4) 선택된 도어에만 LOCK/RELEASE 적용.
- **대안흐름**: ALL 선택 시 좌/우 모두에 적용(단, 한쪽이 접근위험/강제잠금으로 억제 중이면 그 도어는 억제된다).
- **예외흐름**: 미등록 enum·누락 필드 → 명령 거절, 출력 변경 없음.
- **사후조건**: 선택된 도어(억제되지 않은 경우)에만 출력이 반영된다.

### UC-02 주행 중 자동 잠금

- **기본정보**: 차량이 이동을 시작하면 후석 차일드락이 자동으로 활성화된다.
- **사전조건**: `vehicle_speed_kph` 입력이 유효하다.
- **기본흐름**: 1) 차속이 3 km/h 이상이 되는 평가주기 감지 2) 좌/우 출력을 LOCK으로 전환.
- **대안흐름**: 이미 다른 이유로 LOCK 상태였다면 상태만 유지.
- **예외흐름**: 차속 입력이 INVALID/stale이면 UC-09(DEGRADED)로 전이.
- **사후조건**: 좌/우 출력이 LOCK이다.

### UC-03 접근위험 잠금·억제·override

- **기본정보**: 후측방 접근위험이 있는 도어를 잠그고 해제를 억제하되, 운전자가 10초 이내 재입력하면 override로 인정한다.
- **사전조건**: `rear_left_approach_risk`/`rear_right_approach_risk` 입력이 유효하다.
- **기본흐름**: 1) 해당 도어 접근위험 TRUE 감지 2) 해당 도어 LOCK 전환, SUPPRESSED 상태 진입, 원인 기록 3) 운전자가 같은 도어에 RELEASE 재입력 시 경과시간 확인 4) 10초 이내면 OVERRIDE 상태로 전이해 RELEASE 적용, 아니면 억제 유지.
- **대안흐름**: 반대쪽 도어는 독립적으로 판단(SWR-009), 영향받지 않음.
- **예외흐름**: 접근위험 입력이 INVALID → UC-09로 전이.
- **사후조건**: override 성립 시 RELEASE + `override` 이유코드, 아니면 LOCK 유지 + 억제 이유코드.

### UC-04 충돌 확정 시 긴급 해제

- **기본정보**: 충돌이 CONFIRMED되면 다른 모든 로직보다 우선해 좌/우를 해제한다.
- **사전조건**: `crash_status` 입력이 유효하다.
- **기본흐름**: 1) `crash_status=CONFIRMED` 감지 2) 300 ms 이내 좌/우 RELEASE 3) 이후 입력 주기에도 RELEASE 유지(다른 로직이 다시 LOCK시키지 않음).
- **대안흐름**: `crash_status=PENDING`이면 대기 상태 유지, 다른 로직에 영향 없음(가정 A-2).
- **예외흐름**: `crash_status`가 미정 값 → INVALID, 이 UC 트리거 안 됨.
- **사후조건**: 좌/우 출력이 RELEASE로 고정된다.

### UC-05 화재·과온·성인탑승 강제 해제

- **기본정보**: 세 입력 중 하나라도 TRUE이면 강제로 해제한다.
- **사전조건**: 해당 입력이 유효한 boolean이다.
- **기본흐름**: 1) `fire_detected`/`overtemperature_detected`/`adult_present` 중 하나 TRUE 감지 2) 다음 평가주기에 좌/우 RELEASE 3) 트리거된 입력별 이유코드 기록.
- **대안흐름**: 여러 입력이 동시에 TRUE면 모든 이유코드를 함께 기록.
- **예외흐름**: 입력 INVALID → UC-09로 전이.
- **사후조건**: 좌/우 출력이 RELEASE, 이유코드 존재.

### UC-06 ISOFIX 강제 잠금

- **기본정보**: ISOFIX 연결 감지 시 해당 도어를 강제 잠금한다.
- **사전조건**: `isofix_left`/`isofix_right` 입력이 유효하다.
- **기본흐름**: 1) 해당 도어 ISOFIX TRUE 감지 2) 다음 평가주기에 해당 출력 LOCK 3) 반대쪽 출력은 유지.
- **예외흐름**: 입력 INVALID → UC-09로 전이.
- **사후조건**: ISOFIX가 TRUE인 도어만 LOCK.

### UC-07 ignition-off 초기화 해제

- **기본정보**: 시동이 꺼지면 초기 해제 상태로 되돌린다.
- **사전조건**: `ignition_on` 입력이 유효하다.
- **기본흐름**: 1) `ignition_on=FALSE` 감지 2) 다음 평가주기에 좌/우 RELEASE, `OFF` 상태, `ignition_off` 이유코드.
- **사후조건**: 좌/우 출력 RELEASE, 상태 OFF.

### UC-08 sensor_fault 시 출력 유지

- **기본정보**: 센서 결함 시 새 명령을 적용하지 않고 마지막 확정 출력을 유지한다.
- **사전조건**: `sensor_fault` 입력이 유효하다.
- **기본흐름**: 1) `sensor_fault=TRUE` 첫 평가주기 감지 2) 새 명령 적용 보류, 직전 확정 출력 유지 3) `FAULT` 상태와 경고코드 제공.
- **사후조건**: 출력이 이전 값과 동일, FAULT 상태.

### UC-09 입력 stale 시 DEGRADED 전이

- **기본정보**: 필수 안전 입력이 갱신되지 않으면 DEGRADED로 전이한다.
- **사전조건**: 없음(모든 평가주기에서 상시 점검).
- **기본흐름**: 1) 필수 입력의 `source_timestamp_s` 기준 200 ms 초과 미갱신 감지 2) 100 ms 이내 `DEGRADED` 상태 전이.
- **대안흐름**: 형식/범위 오류 입력은 평가 전에 즉시 거절(INVALID), DEGRADED 판정과는 별개로 처리.
- **사후조건**: 상태가 DEGRADED이고 해당 입력 기반 로직은 안전한 기본값으로 처리된다(상세 동작은 Phase 1 설계에서 확정).

### UC-10 상태조회

- **기본정보**: Display(Web 시뮬레이터)가 현재 상태를 조회한다.
- **사전조건**: 없음.
- **기본흐름**: 1) Display가 상태조회 요청 2) SW가 좌/우 출력, `state`, 입력유효성, `priority_reason`, `reason_code`를 응답.
- **예외흐름**: 직렬화 실패 시 HTTP 500(OEM-IF-006).
- **사후조건**: Display에 최신 상태가 표시된다.
